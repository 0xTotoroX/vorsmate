# 风扇控制

总览左侧显示模式，右侧显示实际转速与最高 CPU / GPU 热点温度。展开后有三种模式：

| 模式 | 行为 |
| --- | --- |
| **自动（默认）** | 完全交给 macOS，系统自行决定何时加速；Vorsmate 不以温度阈值干预 |
| **增强散热** | 持续升温后提前加速，提供均衡、强冷；冷却后自动交还系统，保留当前选择 |
| **固定** | 在硬件范围内保持指定转速；不会仅因核心热点超过 90°C 而拒绝或退出，系统严重 / 临界温度压力或读数异常时交还系统 |

增强下方只有两个档位，无需编辑温度参数。均衡确认持续发热约 8 秒，强冷约 4 秒；原始和平滑目标都高于系统当前目标至少 100 RPM 才接管，从当前转速平缓变化。系统已经要求更快转速时继续让系统管理；接管时的系统目标作为本次下界，不是手动状态下持续读取 Apple 的潜在曲线。

增强依据独立的 PMU tdie 参考温度，不直接用显示的最高核心热点套曲线。当前只在已实测的 M4 Mac mini（Mac16,10）启用。两档在持续负载下主动提供额外散热：均衡兼顾声音，强冷更早介入，同温度下转速更高。以下是已核验机型的 1000–4900 RPM 范围的稳定基础目标，点间线性变化；平滑、趋势和接管时系统下界会影响实时值。

| 参考温度 | 均衡 | 强冷 |
| --- | ---: | ---: |
| 65°C | 自动 | 1585 RPM |
| 70°C | 自动 | 2170 RPM |
| 75°C | 1585 RPM | 2755 RPM |
| 80°C | 2170 RPM | 3535 RPM |
| 85°C | 2755 RPM | 4315 RPM |
| 90°C | 3730 RPM | 4900 RPM |
| 95°C | 4900 RPM | 4900 RPM |

表中“自动”指尚未接管时保持系统控制；曾经接管后，还需满足下方冷却回差才归还。这些参数是本项目的散热偏好，不是 Apple 公布的芯片温度极限，也不适用于其他温度来源。未核验机型或参考读数缺失时保持自动，不回退到热点驱动。悬停风扇行可以查看当前参考温度。

PMU 读取使用动态解析的非公开 IOKit 温度接口，后续系统更新可能改变可用性；接口缺失时停止增强，保留系统自动控制。

参考温度按均衡 8 / 25 秒、强冷 4 / 30 秒的升温 / 降温时间常数平滑。连续上升至少 4 秒后，分别参考未来 6 / 10 秒的趋势，提前量最多 2 / 4°C；趋势只调整目标，不绕过接管确认。均衡 / 强冷每秒加速最多 150 / 300 RPM，降速先保持 20 / 30 秒，再每秒最多降低 60 / 80 RPM。小于 100 RPM 的目标波动保持当前值，全速和归还端点仍可到达。

温度下降到接管前系统目标对应的曲线温度再低 3°C，原始和平滑读数满足条件 30 / 45 秒且已完成缓降后归还系统。系统报告严重或临界温度压力，或读数不可用时立即交还自动；健康状态连续稳定 10 秒后重新确认持续发热。连接暂未确认时明确显示“待确认”。

低温不等于强制停转：已核验 M4 Mac mini 的最低转速为 1000 RPM。模式为自动且读到约 1000 RPM 时风扇仍在运行，只是可能很难听见。

调速通过独立系统助手完成：使用 Apple 开发签名构建，将应用放入 `/Applications`，再点击“风扇 → 启用调速”，由用户完成系统授权。没有助手仍能监控真实温度和转速。不要同时运行其他风扇控制软件。

连接断开、12 秒未续期、硬件故障或外部接管时终止本次调速。正常退出和睡眠也释放控制，重开应用回到自动。等待增强不登记硬件拥有权；实际写入前保存恢复责任，冷却归还时清除，回读失败则保留责任重试。安装维护可在正常退出后带 `--maintenance` 启动，使用临时菜单中的“停用风扇助手”；确认恢复成功后才注销服务。实际验收范围见[验收记录](verification.md)。


## 安装与更新

下载的预览版已包含同团队签名的应用与助手。先将应用放入“应用程序”，打开后在风扇区启用调速，按 macOS 提示允许后台活动并完成管理员授权。开发签名不等于 Developer ID 分发或 Apple 公证；其他用户电脑的首次安装、授权仍待独立验收。

若旧版已启用助手，更新前先选择自动并确认交还系统，退出应用；使用 `open /Applications/Vorsmate.app --args --maintenance --show` 打开旧版，在临时菜单中“停用风扇助手”，确认成功后退出。再替换应用，正常启动并重新启用助手。不要直接覆盖正在调速的助手，或让旧助手和新界面长期混用。
